# گزارش تغییرات (Changelog)

## [0.3.1] — ۲۰۲۶-۱۰-۲۴ — «فاز اصلاح پیش از انتشار»

اصلاح یکپارچگی نصب‌کننده و بسته‌بندی، پیش از افزودن هر قابلیت جدید (طبق وظیفهٔ v0.3.1).

### ساختار Git و انتشار (§۲ وظیفه)
- مخزن پایتون از gitlinkِ بدون `.gitmodules` به ساختار اصلی منتقل شد (fold) — clone تمیز حالا کل محصول را دارد؛ تاریخچهٔ ۷ کامیت آن در شاخهٔ `archive/hem-python` حفظ شد.
- **بحران کشف‌شده:** سطر `test` در `.gitignore` باعث شده بود کل تست‌های agent (و `test/server.ts` که build ویندوز به آن وابسته است) هرگز وارد گیت نشود — حذف شد و ۲۱ فایل test/ به گیت آمد.
- خروجی‌های build و داده‌های توسعه هرگز وارد گیت/بسته نمی‌شوند: `.env`، `db/`، `prisma/`+`src/lib/db.ts` (اسکلت مرده — محصول پایگاه‌داده ندارد)، `download/`، `ui-out/` — release.sh با allowlist + خودآزمایی (حالا شامل ui-out/prisma/db.ts) و `git archive HEAD:headscale-easy-manager`.

### مسیر نصب‌کننده (§۱ وظیفه)
- مسیر توسعه‌دهندهٔ `/home/z/my-project/headscale-easy-manager` از همهٔ مسیرهای اجرایی حذف شد. زنجیرهٔ حل: `HEM_PROJECT_ROOT` → `installer/` کنار فایل اجرایی (بستهٔ ویندوزی آن را دارد) → checkout توسعه؛ اگر هیچ‌کدام نبود، خطای روشن با فهرست همهٔ مسیرهای امتحان‌شده — هرگز «آماده/موفق» اعلام نمی‌شود (`installerRootStatus` + لاگ صادقانهٔ راه‌اندازی).
- بستهٔ ویندوزی حالا `installer/` را کنار exe بسته‌بندی می‌کند؛ UI همیشه از ابتدا ساخته می‌شود (بدون بازاستفادهٔ `ui-out`).

### امنیت agent (§۴ وظیفه)
- **WebSocket بدون احراز هویت** (آسیب‌پذیری واقعی) بسته شد: اتصال socket.io بدون هدر/کوکی معتبر بلافاصله قطع می‌شود و هیچ رویداد حساسی نمی‌گیرد.
- تبادل `?token=` **یک‌بارمصرف** شد: کوکی جلسه‌ای HttpOnly/SameSite=Strict (بدون Max-Age) + 303 که نشانی را بدون token تمیز می‌کند؛ بازیابی لینک از تاریخچهٔ مرورگر دیگر کوکی نمی‌سازد. `token` در query هرگز روش احراز هویت API نیست. مقایسه‌ها timing-safe شدند.
- تست‌های مثبت/منفی جدید: `test/auth.test.ts` (HTTP/Bootstrap/WS — ۱۹ تست).

### بازیابی و پایداری (§۵ وظیفه)
- `test/recovery.test.ts` (agent): لغوی واقعیِ وسط عملیات روی SSH زنده + نتیجهٔ صادقانهٔ «لغوشده» (هرگز موفق جعلی) + اجرای دوباره پس از خطا.
- `tests/test_recovery_rerun.py`: خطا → اصلاح → دوباره → موفقیت واقعی ۱۷گامی؛ اجرای مجدد → همان خروجی (idempotent در سطح dry-run).

### CI (§۳.۴ وظیفه)
- GitHub Actions با دو job: **windows** (کامپایل و اجرای واقعی hem-manager.exe روی windows-latest: توکن یک‌بارمصرف، 401/200، installer/ بسته‌بندی‌شده، UI فارسی، SHA-256) و **linux** (clone تمیز: lint/typecheck/docs/build/pytest/release/build-windows).

### آزموده‌نشده (صادقانه)
- نصب واقعی روی اوبونتوی تازه با systemd: در سندباکس/CI ممکن نیست (systemd نیست) — dry-run و منطق واقعی با ۱۰۵+ تست پوشش داده شده؛ اجرای کامل نیازمند VPS آزمایشی واقعی است.
- اتصال SSH به VPS واقعی در CI آزموده نمی‌شود (نیازمند سرور واقعی)؛ در سندباکس با سرور آزمایشی ۲۲۲۲ پوشش داده شده است.

## [0.3.0] — ۲۰۲۶-۱۰-۲۴

نسخهٔ «کنسول واقعی»: از نصب‌کنندهٔ CLI به محصول کامل — برنامهٔ ویندوزی با رابط وب فارسی و اتصال SSH واقعی به سرور شما. همهٔ ۱۱ ایراد ممیزی AUDIT-2025-10 بسته شد.

### اصلاح‌شده — ممیزی AUDIT-2025-10 (ایرادهای ۴.۱ تا ۴.۱۱)
- **۴.۱** dry-run حالا hsctl واقعی را از مخزن سورس اجرا می‌کند و کد خروج واقعی را منتشر می‌کند (نه همیشه ۰)
- **۴.۲** ترتیب گام‌ها اصلاح شد (جمع‌آوری ورودی‌ها قبل از برنامه‌ریزی)؛ در حالت غیرتعاملی اجرای برنامه فقط با رضایت صریح `--yes`
- **۴.۳** نمونهٔ تنظیمات تک‌منبعی شد (`examples/hem-install.conf.example`) و FACTS §4 با باینری واقعی v0.29.5 اصلاح شد
- **۴.۴** وضعیت‌های نهایی نصب صادقانه شد: `verified` / `service_not_ready` / `pending_verification` / `partial_failure` / `full_success` — پیام «نصب کامل شد» فقط با سند واقعی چاپ می‌شود
- **۴.۵** چک‌سام SHA-256 رسمی در «همهٔ» مسیرها الزامی شد (تعاملی، غیرتعاملی، dry-run، ارتقا) — بدون checksum هیچ دانلودی انجام نمی‌شود
- **۴.۶** ایمن‌سازی UFW: snapshot قواعد و سرویس‌های شنیده‌شده قبل از هر تغییر، رضایت صریح کاربر، rollback واقعی قواعد
- **۴.۷** rollback ارتقا واقعی شد: بستهٔ قبلی headscale برمی‌گردد، پیکربندی بازگردانی و سلامت بررسی می‌شود
- **۴.۸** راستی‌آزمایی پشتیبان per-file شد: هش تک‌تک فایل‌های manifest با محتوای داخل آرشیو تطبیق داده می‌شود
- **۴.۹** محتوای آموزش رابط وب در زمان ساخت تولید می‌شود (بدون خواندن فایل در زمان اجرا) — سازگار با بستهٔ استاتیک
- **۴.۱۰** `typescript.ignoreBuildErrors` حذف و خروجی `static export` شد؛ بیلد واقعی production با صفر خطای تایپ راستی‌آزمایی شد
- **۴.۱۱** بستهٔ انتشار با اسکریپت `release.sh` و allowlist سخت‌گیرانه تمیز می‌شود — بدون `.git`، `.env`، دیتابیس توسعه، کش‌ها و لاگ‌ها + خودآزمایی داخل اسکریپت

### افزوده‌شده
- **hem-agent** — بک‌اند مدیریت واقعی با اتصال SSH (ssh2): جریان کامل TOFU اثرانگشت میزبان، مغایرت کلید با هشدار امنیتی، مخزن اسرار (ویندوز: Credential Manager)، حسابرسی بدون هیچ رمز/کلید کامل، allowlist کنسول (بدون شل آزاد)، اجرای زندهٔ نصب با استریم لاگ، پشتیبان/بازیابی/ارتقای واقعی hsctl
- **رابط وب فارسی کامل (کنسول)**: مرکز اتصال با پروفایل‌ها، داشبورد زنده از دادهٔ واقعی سرور، ویزارد نصب ۵ مرحله‌ای (کاوش سرور → تنظیمات از اسکیمای واقعی → Dry-Run با رضایت صریح → اجرای زنده → نتیجهٔ صادقانه)، مدیریت کاربران/دستگاه‌ها/کلیدها/مسیرها/سیاست دسترسی، پیکربندی با configtest، سرویس و لاگ، پشتیبان و ارتقا، کنسول پیشرفتهٔ امن — همه با عملیات واقعی روی سرور
- **بستهٔ ویندوز تک‌فایلی** (mini-services/hem-agent/packaging — exe تولیدشده با Bun compile و UI استاتیک embed)
- **فصل ۱۵ مستندات فارسی** (docs/fa)
- README فارسی محصول در ریشهٔ بسته (README-FA.md)

### تست‌ها
- پایتون: ۱۰۳ تست پاس (واحد/ماژول — نصب‌کننده، چک‌سام، سلامت صادقانه، فایروال، rollback ارتقا، پشتیبان per-file)
- hem-agent: ۸۳ تست پاس با سرور SSH آزمایشی واقعی (ssh2) و باینری واقعی headscale 0.29.5

### محدودیت‌های شناخته‌شده
- تست یکپارچهٔ واقعی نصب روی اوبونتوی تمیز (apt/systemd/UFW/Caddy واقعی) همچنان به VPS آزمایشی نیاز دارد — در محیط توسعه با سرور SSH آزمایشی و dry-run واقعی پوشش داده شده است.
- ارتقا باید نسخه‌به‌نسخه انجام شود (قید رسمی Headscale)؛ `hsctl update` هشدار می‌دهد.

## [0.1.0] — نسخه اول

### افزوده‌شده
- نصب‌کننده تعاملی و خودکار Headscale v0.29.5 روی Ubuntu Server 22.04/24.04 (amd64/arm64)
- بررسی پیش‌نیازها (preflight): سیستم‌عامل، معماری، دیسک، RAM، sudo، پورت‌ها، سرویس‌های موجود
- تشخیص و احترام به سرویس‌های موجود (Caddy/Headscale/nginx/… ) با پشتیبان‌گیری قبل از هر تغییر
- پیکربندی Headscale + Caddy (TLS خودکار) + فایروال UFW با حفظ دسترسی SSH
- ابزار مدیریت `hsctl`: status, doctor, logs, users, devices, preauth, routes, backup, restore, update, config, cameras, learn, explain, report, uninstall
- پشتیبان‌گیری/بازیابی کامل (SQLite با .backup امن + کلیدها + پیکربندی + manifest)
- مدیریت دوربین‌های مداربسته و دستگاه ضبط Dahua از طریق Subnet Router
- مرکز آموزش فارسی (۱۴ فصل) به‌همراه `hsctl learn` و `hsctl explain`
- گزارش تشخیصی قابل‌ارسال با حذف خودکار اطلاعات حساس
- حالت `--dry-run` برای نمایش تغییرات بدون اعمال

### محدودیت‌های شناخته‌شده

  در محیط توسعه فقط منطق (parserها، تولید پیکربندی، state، پشتیبان) تست واحد شده است.

# ممیزی عمیق — Headscale Easy Manager v0.2.0 (اکتبر ۲۰۲۵)

این سند نتیجهٔ ممیزی کامل مخزن بر اساس سورس **فعلی** است (نه نسخهٔ قبلی). هر ایراد با شمارهٔ خط و قطعه‌کد تطبیق داده شده است.
منبع واحد حقیقت فنی: `docs/FACTS.md` + باینری واقعی headscale v0.29.5 (راستی‌آزمایی‌شده در این ممیزی).

## ۰. یافته‌های جدید ممیزی (خارج از فهرست قبلی)

1. **`routes` به‌عنوان دستور سطح‌بالای headscale وجود ندارد** (خروجی واقعی: `Error: unknown command "routes"`) — FACTS §۴ درست است ولی hsctl باید از `nodes list-routes` / `nodes approve-routes` استفاده کند. ✓ (در hsctl همین‌طور است)
2. **`preauthkeys list` در 0.29.5 فلگ `--user` ندارد** (خروجی واقعی `--help`: فقط `-h`) — برخلاف FACTS §۴ که می‌گوید `preauthkeys list --user <USER_ID>`. کلیدها همیشه به‌صورت ماسک‌شده برمی‌گردند. → FACTS و همهٔ فراخوان‌ها باید اصلاح شوند.
3. **`preauthkeys create` فلگ صحیح: `-u, --user uint`** (تست واقعی موفق) + `-e, --expiration`، `--reusable`، `--ephemeral`، `--tags`.
4. `install.sh` خط ۱۷۴–۱۷۵: به‌دلیل `set -euo pipefail`، اگر hsctl با کد غیرصفر خارج شود، اسکریپت **بلافاصله** می‌میرد و پیام خطای خط ۱۸۰ هرگز چاپ نمی‌شود (`RC=$?` هرگز اجرا نمی‌شود).
5. `ufw_enable()` نتیجهٔ فعال‌سازی را برنمی‌گرداند به فراخوانندهٔ `firewall_setup` (خط ~۱۸۳ firewall.py): اگر enable شکست بخورد، نصب با موفقیت ادامه می‌یابد.
6. SHA-256 بستهٔ deb رسمی v0.29.5 در این ممیزی مستقل دانلود و تطبیق شد: `9e8ec12a65229435863a2cdf5082853c282808e845efd3a1f0b0c02b8f84d723` ✓ مطابق `constants.py`.

## ۴. معماری هدف (تصمیم مستند)

**فرم نهایی: Windows exe تک‌فایلی (Bun compile) + Web UI فارسی در مرورگر محلی + سرویس agent با اتصال SSH واقعی (ssh2).**

- `mini-services/hem-agent/` — سرویس محلی (Bun/Node، پورت ۳۰۰۵، فقط 127.0.0.1): موتور SSH واقعی (ssh2)، مدیریت پروفایل + اثرانگشت میزبان (TOFU با تأیید صریح)، مخزن اسرار (ویندوز: Credential Manager/PasswordVault؛ لینوکس: فایل 0600 — صادقانه مستند)، آداپتورهای CLI واقعی headscale 0.29.5، اجراکنندهٔ نصب (آپلود مخزن + `install.sh --config answers --yes` غیرتعاملی با خروجی زنده)، REST + socket.io.
- همان کد agent در ویندوز با `bun build --compile --target=bun-windows-x64` به exe تبدیل می‌شود + UI استاتیک embed.
- در sandbox: UI روی پورت ۳۰۰۰، agent روی ۳۰۰۵، درخواست‌ها با `?XTransformPort=3005` از دروازه عبور می‌کنند (قرارداد محیط).
- تست یکپارچه واقعی: سرور SSH آزمایشی (ssh2 server روی 127.0.0.1:2222) + باینری واقعی headscale 0.29.5 (دانلود و SHA-256 تأییدشده، در حال اجرا با socket کاربر) — کل زنجیرهٔ مدیریت واقعی است؛ فقط مسیر «نصب روی اوبونتوی تمیز» به VPS واقعی نیاز دارد (صادقانه مستند می‌شود).

## ۵. تصمیم‌های فنی مستند

1. **ssh2 (pure-JS)** به‌جای ssh CLI: پشتیبانی password+key در همان پروسه، استریم زنده، hostkey callback — تست roundtrip واقعی زیر Bun انجام شد ✓
2. **اجرای نصب از طریق مخزن پایتون موجود** (نه بازنویسی): agent فقط آپلود/اجرای `install.sh` است؛ منبع واحد حقیقت نصب حفظ می‌شود. اصلاحات 4.1/4.2/4.5 مسیر غیرتعاملی را امن می‌کنند.
3. **sudo**: تشخیص `sudo -n true`؛ در صورت نیاز به رمز، `sudo -S -p ''` با رمز در stdin (هرگز در argv/لاگ).
4. **حالت اجرای headscale در پروفایل**: `system-sudo` (پیش‌فرض VPS) | `custom` (باینری/config دلخواه — برای سرور آزمایشی) — یک مسیر کد، پوشش‌دهندهٔ هر دو.
5. **PreAuthKey**: کلید کامل فقط یک‌بار پس از ساخت نمایش/ارسال می‌شود (خروجی واقعی list ماسک است) و هرگز در لاگ/audit ذخیره نمی‌شود.
6. حذف endpointهای `/api/project/*` از UI محصولی (۴.۹)؛ مرکز آموزش از محتوای build-time می‌خواند (سازگار با static export و exe).

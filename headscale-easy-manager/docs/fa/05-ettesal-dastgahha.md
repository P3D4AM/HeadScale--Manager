# فصل پنجم: اتصال دستگاه‌ها

در این فصل یاد می‌گیرید:

- تفاوت مهم «آدرس سرور کنترل» با «آدرس CRM دفتر» (اشتباه رایج!)
- گوشی اندروید را به شبکه وصل کنید
- کامپیوتر ویندوزی را وصل کنید
- لپ‌تاپ یا سرور لینوکسی را وصل کنید
- وضعیت macOS و iOS (با راهنمای رسمی سرور خودتان)
- دستگاه تازه‌وارد را روی سرور تأیید کنید (جریان Web Auth)
- با «کلید از پیش تأییدشده» بدون سؤال و جواب وصل شوید
- IP دستگاه را ببینید، اتصال را تست کنید و موقتاً قطع/وصل کنید

در همهٔ این فصل فرض ما: سرور روی `https://headscale.example.com` نصب و سالم است (فصل چهارم) و نام کاربر اولِ شبکه `admin` است.

---

## ۵.۱ اول اشتباه رایج را دور بریزیم: دو آدرسِ متفاوت

قبل از هر کلیکی، این جدول را خوب ببینید. این دو آدرس **هیچ ربطی به هم ندارند** و قاطی‌کردنشان رایج‌ترین دلیل سردرگمی کاربران تازه‌کار است:

| | آدرس سرور کنترل (Headscale) | آدرس CRM دفتر |
|---|---|---|
| نمونه | `https://headscale.example.com` | `http://192.168.1.220:800` |
| چیست؟ | «میزبان پذیرشِ» شبکهٔ VPN شما — روی VPS | یک سرویس (نرم‌افزار CRM) داخل شبکهٔ LAN دفتر |
| چه وقت لازم می‌شود؟ | **فقط یک بار**، موقع اضافه‌کردن هر دستگاه به شبکه | **هر روز**، وقتی می‌خواهید با CRM کار کنید |
| کجا اجرا می‌شود؟ | روی سرور ابری (VPS) | روی یک کامپیوتر داخل دفتر |
| چه چیزی به آن وصل می‌شود؟ | کلاینت Tailscale (برای عضویت) | مرورگر یا برنامهٔ CRM شما |
| بدون VPN قابل دسترسی؟ | بله (روی اینترنت عمومی است) | خیر (IP خصوصیِ پشت NAT است — فصل اول) |

خلاصهٔ داستان:

1. **یک بار** به دستگاه می‌گویید «از سرورِ `https://headscale.example.com` عضو شو».
2. **برای همیشه** بعد از آن، دستگاهِ عضو می‌تواند آدرس‌های داخل شبکهٔ دفتر (مثل `http://192.168.1.220:800`) را باز کند — به شرطی که پل دفتر (فصل ششم) آماده باشد.

پس آدرس سرور را در جای امنی یادداشت کنید؛ به‌زودی خیلی کم به آن نیاز پیدا می‌کنید.

## ۵.۲ اندروید

### نصب برنامه

کلاینت **رسمی Tailscale** را از **Google Play** یا **F-Droid** نصب کنید (نام بسته: Tailscale). این همان برنامهٔ معروف است؛ فقط قرار است به‌جای سرویس ابری، به سرور خودتان وصلش کنیم.

### اتصال به سرور خودتان

در برنامهٔ Tailscale:

1. وارد **تنظیمات (Settings)** شوید.
2. به بخش **Accounts** بروید.
3. منوی **سه‌نقطه (⋮)** بالای صفحه را باز کنید.
4. گزینهٔ **Use an alternate server** («استفاده از سرور جایگزین») را بزنید.
5. آدرس سرور خود را وارد کنید: `https://headscale.example.com`
6. تأیید کنید.

(نام دقیق منوها بین نسخه‌های برنامه ممکن است کمی جابه‌جا شود؛ در نسخه‌های جدید همین مسیر با همین نام‌ها موجود است.)

برنامه به سرور وصل می‌شود و دستگاه شما «در انتظار تأیید» می‌ماند — ادامه در بخش ۵.۶ (جریان تأیید). بعد از تأیید، آیکون کلید در نوار وضعیت اندروید ظاهر می‌شود؛ یعنی VPN فعال است.

> **راه میان‌بر:** اگر سرور برایتان «کلید از پیش تأییدشده» ساخته باشد (بخش ۵.۷)، در همان منوی سه‌نقطه گزینهٔ **Use an auth key** را بزنید و کلید را وارد کنید؛ بدون هیچ تأیید اضافه‌ای عضو می‌شوید.

## ۵.۳ ویندوز

### نصب برنامه

کلاینت رسمی ویندوز را از سایت رسمی دانلود و نصب کنید: `https://tailscale.com/download` (نصب‌اش مثل هر برنامهٔ ویندوزی، بعد از بعدی).

### اتصال به سرور خودتان

برنامه را نصب کرده و اجرا کنید، سپس **PowerShell** را باز کنید (از منوی Start تایپ کنید `powershell` و Enter):

```powershell
tailscale login --login-server https://headscale.example.com
```

توضیح خط‌به‌خط:

- `tailscale` : فرمان کلاینت (بعد از نصب، در PATH ویندوز هست)
- `login` : عملیات «عضویت در یک سرور»
- `--login-server` : «به‌جای سرور پیش‌فرض Tailscale، به این سرور وصل شو»
- `https://headscale.example.com` : آدرس سرور شما

مرورگر باز می‌شود و صفحهٔ تأیید سرور شما را می‌بیند — ادامه در بخش ۵.۶.

**یا از رابط گرافیکی:** در نسخه‌های جدید کلاینت ویندوز، آیکون Tailscale در System Tray (کنار ساعت) وضعیت اتصال را نشان می‌دهد؛ روش توصیه‌شدهٔ رسمی برای سرور جایگزین همان دستور PowerShell بالاست که یک‌بار اجرا می‌کنید و تا همیشه ذخیره می‌ماند.

## ۵.۴ لینوکس

نصب کلاینت رسمی با اسکریپت رسمی (روی اوبونتو/دبیان — روی خود VPS هم اگر خواستید، همین دستور است):

```bash
curl -fsSL https://tailscale.com/install.sh | sh
```

توضیح خط‌به‌خط:

- `curl -fsSL https://tailscale.com/install.sh` : دانلود اسکریپت نصب رسمی از سایت رسمی Tailscale
- `| sh` : اجرای مستقیم همان اسکریپت (نصب بستهٔ رسمی کلاینت برای توزیع شما)

سپس اتصال به سرور خودتان:

```bash
sudo tailscale up --login-server https://headscale.example.com
```

توضیح خط‌به‌خط:

- `sudo` : چون باید شبکهٔ سیستم را پیکربندی کند
- `tailscale up` : روشن‌کردن کلاینت و شروع عضویت
- `--login-server` : آدرس سرور کنترل شما (به‌جای سرویس ابری پیش‌فرض)

خروجی نمونه:

```text
To authenticate, visit:

        https://headscale.example.com/register/0123456789abcdef
```

این آدرس را در مرورگر باز کنید — ادامه در بخش ۵.۶.

## ۵.۵ macOS و iOS

کلاینت‌های رسمی Tailscale برای **macOS** و **iOS** (و حتی tvOS) پشتیبانی می‌شوند و می‌توانند به سرور Headscale شما وصل شوند؛ فقط چون نکات اختصاصی‌تری (مثل نصب نسخهٔ درست از App Store یا نسخهٔ Standalone در مک) دارند، برایشان راهنمای آماده روی خودِ سرور شما وجود دارد!

در مرورگر باز کنید:

```text
https://headscale.example.com/apple
```

این صفحهٔ راهنمای رسمیِ خودِ Headscale است که دقیقاً برای سرورِ شما تولید می‌شود و مراحل اتصال Apple را قدم‌به‌قدم نشان می‌دهد. (صفحهٔ مشابهی هم برای ویندوز هست: `https://headscale.example.com/windows`.) در کنارش، مستندات رسمی Tailscale برای این پلتفرم‌ها مرجع تکمیلی شماست.

## ۵.۶ جریان تأیید دستگاه (Web Auth)

وقتی دستگاهی تازه به سرور وصل می‌شود، برای امنیت، خودکار عضو نمی‌شود. جریان کامل:

```text
دستگاه تازه                        سرور شما                      شما (مدیر)
   │                                 │                              │
   │ tailscale up --login-server …   │                              │
   │────────────────────────────────►│  «کسی در در زده!»            │
   │                                 │                              │
   │ آدرس register/... در ترمینال    │                              │
   │◄────────────────────────────────│                              │
   │                                 │                              │
   │ آدرس را در مرورگر باز می‌کنید    │                              │
   │ ────────────────► صفحهٔ سرور:   │                              │
   │                 «این دستور را روی سرور بزنید»                  │
   │                 headscale auth register --auth-id <AUTH_ID> …  │
   │                                 │                              │
   │                                 │◄─────────────────────────────│
   │                                 │  اجرای همان دستور (با SSH)   │
   │                                 │  «خوش آمدی!»                 │
   │        ✔ عضو رسمی شبکه          │                              │
   │◄────────────────────────────────│                              │
```

به زبان ساده، سه قدم:

**قدم ۱ — دستگاه آدرس می‌دهد:** همان‌طور که در بخش‌های قبل دیدید، ترمینال یا برنامه یک آدرس (`https://headscale.example.com/register/...`) به شما می‌دهد. آن را در مرورگر باز کنید.

**قدم ۲ — صفحهٔ سرور دستور تأیید را نشان می‌دهد:** صفحه‌ای باز می‌شود با پیامی شبیه این:

```text
Node registration

Run the command below in the headscale server to add this node
to your network:

headscale auth register --auth-id 01234567-89ab-cdef-0123-456789abcdef --user USERNAME
```

**قدم ۳ — روی سرور همان دستور را اجرا کنید:** وارد SSH سرور شوید (فصل چهارم) و دستور را با مقادیر واقعی اجرا کنید — فقط به‌جای `USERNAME` نام کاربر شبکهٔ خودتان را بگذارید:

```bash
headscale auth register --user admin --auth-id <AUTH_ID>
```

توضیح خط‌به‌خط:

- `headscale` : فرمان مدیریتی سرور
- `auth register` : «ثبتِ» یک دستگاهِ در انتظار تأیید
- `--user admin` : دستگاه زیر نام کاربری `admin` ثبت شود
- `--auth-id <AUTH_ID>` : همان شناسه‌ای که صفحهٔ مرورگر نشان داد (هر دستگاه در هر بار ثبت یک شناسهٔ یکتا می‌گیرد؛ مقدار واقعی‌اش را از صفحه کپی کنید)

خروجی نمونه:

```text
Node laptop-ali registered
```

همین! دستگاه شما الان عضو شبکه است. دو دستور خواهرِ این دستور هم وجود دارد: `headscale auth approve --auth-id <AUTH_ID>` (تأیید یک درخواست در حال انتظار) و `headscale auth reject --auth-id <AUTH_ID>` (رد کردن آن).

> **ابزار خودمان:** در نسخه‌های بعدی ابزار مدیریت این پروژه، این تأیید از طریق `hsctl devices` هم قابل انجام خواهد بود تا حتی لازم نشود دستور headscale را دستی بنویسید. در زمان نگارش این فصل، روش رسمی همان دستور `headscale auth register` است.

## ۵.۷ روش کلید از پیش تأییدشده (Preauth Key)

اگر نمی‌خواهید هر دستگاه را با جریان مرورگر تأیید کنید (مثلاً ده‌ها دستگاه دارید یا از راه دور به دستگاه دسترسی ندارید)، **کلید از پیش تأییدشده (Preauth Key)** راه‌حل است: روی سرور یک کلید می‌سازید، آن را یک بار روی دستگاه وارد می‌کنید؛ دستگاه بدون سؤال و جواب عضو می‌شود.

**روی سرور — ساخت کلید برای کاربر `admin`:**

```bash
hsctl preauth create admin
```

یا با دستور خام headscale. ⚠️ دقت: در این دستور، `--user` **شناسهٔ عددی کاربر** است نه نامش! اول با `headscale users list` ستون ID کاربر را ببینید، بعد مثلاً برای کاربری با شناسهٔ `1`:

```bash
headscale preauthkeys create --user 1
```

خروجی نمونه (کلید واقعی هرگز در مستندات نمی‌آید؛ این قالب عمومی آن است):

```text
tskey-auth-<AUTH_KEY>
```

**روی دستگاه — اتصال با کلید:**

- لینوکس:

```bash
sudo tailscale up --login-server https://headscale.example.com --authkey <AUTH_KEY>
```

- اندروید: در همان منوی سه‌نقطهٔ بخش ۵.۲، گزینهٔ **Use an auth key** و وارد کردن `tskey-auth-...`

نکته‌های مهم:

- کلیدها به‌صورت پیش‌فرض **یک‌بارمصرف** و با **انقضای ۱ ساعت** ساخته می‌شوند؛ بعد از مصرف یا انقضا بی‌اثرند (این یعنی اگر جایی لو رفت، عمرش کوتاه است).
- برای دستگاه‌های زیاد می‌توان نسخهٔ چندمصرف ساخت: `hsctl preauth create admin --reusable`
- کلید را مثل رمز نگه دارید؛ هر کس آن را داشته باشد می‌تواند دستگاهش را بدون تأیید وارد شبکهٔ شما کند.
- فهرست کلیدهای کاربر: `hsctl preauth list admin`

### ساخت کلید از رابط گرافیکی (برنامهٔ ویندوزی)

اگر از برنامهٔ ویندوزی استفاده می‌کنید، لازم نیست دستور بزنید: در بخش **«کلیدها»**، با انتخاب کاربر و تنظیم گزینه‌ها (قابل استفاده مجدد، اعتبار، برچسب‌ها) کلید ساخته می‌شود. دو قاعدهٔ امنیتی همان است و از خود سرور اجرا می‌شود:

- مقدار کامل کلید فقط **یک‌بار** در یک کارت امن نمایش داده می‌شود (با هشدار «این کلید دیگر نمایش داده نمی‌شود») — همان‌جا کپی کنید؛
- بعد از بستن کارت، فهرست فقط نسخهٔ ماسک‌شده را نشان می‌دهد — منطق عمدی و کاملاً یکسان با CLI.

راهنمای کامل برنامهٔ ویندوزی: [فصل پانزدهم](15-barnameh-windows.md).

## ۵.۸ بعد از اتصال: IP، تست و وضعیت

### IP دستگاه شما در شبکهٔ VPN

روی دستگاهی که وصل شده:

```bash
tailscale ip -4
```

خروجی نمونه:

```text
100.64.0.2
```

این «شمارهٔ صندلی» شما در شبکهٔ VPN است (رنج `100.64.0.0/10` — فصل سوم، بخش ۳.۱۰). روی هر دو دستگاهی که وصل کرده‌اید این دستور را بزنید تا IPهایشان را ببینید.

### تست اتصال بین دو دستگاه

از دستگاه اول، دستگاه دوم را پینگ کنید (به‌جای نام، IP دوم را هم می‌توانید بگذارید):

```bash
tailscale ping my-laptop
```

خروجی نمونه (اوج موفقیت: مسیر مستقیم):

```text
pong from my-laptop (100.64.0.3) via 203.0.113.45:41231 in 18ms
```

اگر چند پینگ اول `via DERP(...` نشان داد نگران نشوید؛ یعنی فعلاً از رله می‌رود و معمولاً بعد از چند ثانیه به مسیر مستقیم (`via IP:پورت`) می‌رسد.

### وضعیت کلی

```bash
tailscale status
```

خروجی نمونه (سه عضو: گوشی، لپ‌تاپ و دستگاه دفتر):

```text
100.64.0.2    my-phone        admin@   android   -
100.64.0.3    my-laptop       admin@   windows   -
100.64.0.1    office-router   admin@   linux     -
```

یعنی: سه دستگاهِ شما، سه IP از رنج VPN، همه زیر کاربر `admin` و همه آنلاین.

## ۵.۹ قطع و وصل‌کردن اتصال

روی دستگاه‌های لینوکسی/ترمینال‌دار:

```bash
sudo tailscale down
```

(قطع موقت: دستگاه از شبکه خارج می‌شود ولی عضویتش می‌ماند)

```bash
sudo tailscale up
```

(وصل مجدد — دقت کنید: **دیگر لازم نیست `--login-server` بدهید**؛ سرور در دستگاه ذخیره شده و فقط همین دستور کوتاه کافی است)

روی اندروید و ویندوز همین کار از رابط گرافیکی برنامه (کلید روشن/خاموش) انجام می‌شود.

> آیا تا اینجا می‌توانید CRM دفتر را باز کنید؟ **هنوز نه** — چون دستگاهی داخل دفتر هنوز «پل» نشده است. دقیقاً همین کار فصل بعد است.

## خلاصه فصل

- «آدرس سرور کنترل» (`https://headscale.example.com`) فقط برای عضویت است؛ «آدرس CRM» (`192.168.1.220:800`) برای کار روزمره. این دو را قاطی نکنید.
- اندروید: کلاینت رسمی Tailscale از Play/F-Droid + مسیر Settings → Accounts → ⋮ → Use an alternate server.
- ویندوز: کلاینت رسمی از tailscale.com/download + دستور `tailscale login --login-server ...` در PowerShell.
- لینوکس: نصب با `curl -fsSL https://tailscale.com/install.sh | sh` و اتصال با `sudo tailscale up --login-server ...`.
- macOS/iOS: کاملاً پشتیبانی می‌شوند؛ راهنمای رسمی روی خود سرور شما: `https://دامنه/apple` (و `/windows`).
- تأیید دستگاه تازه: دستگاه آدرس می‌دهد ← مرورگر `AUTH_ID` نشان می‌دهد ← روی سرور `headscale auth register --user admin --auth-id <AUTH_ID>`.
- راه سریع‌تر: `hsctl preauth create admin` روی سرور و `--authkey <AUTH_KEY>` روی دستگاه.
- ابزارهای روزمره: `tailscale ip -4`، `tailscale ping <نام-یا-IP>` و `tailscale status`؛ قطع/وصل با `tailscale down` / `tailscale up`.
- کلید از پیش تأییدشده را می‌توان از CLI (`hsctl preauth create`) یا از رابط گرافیکی (بخش «کلیدها») ساخت؛ در هر دو، نمایش کامل فقط یک‌بار است.

همهٔ دستگاه‌های شخصی وصل‌اند؛ حالا وقت ساخت «پل دفتر» است تا از هر جای دنیا به CRM برسیم: [فصل ششم: دسترسی از بیرون به شبکه دفتر](06-dastresi-shabake-daftar.md)

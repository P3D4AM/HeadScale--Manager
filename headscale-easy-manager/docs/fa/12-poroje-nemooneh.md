## در این فصل یاد می‌گیرید

- تمام آموخته‌های فصل‌های ۱ تا ۹ را در **یک پروژه واقعی و پیوسته** به کار ببندید
- از تهیه سرور و دامنه تا بازکردن CRM دفتر روی گوشی با اینترنت همراه، در ۱۰ مرحله
- برای هر مرحله، همان دستورها و پاسخ‌هایی که واقعاً می‌بینید را تمرین کنید
- در پایان، یک **خطای عمدی بی‌خطر** بسازید و خودتان عیب‌یابی کنید

### قصه ما

آقای رضایی مدیر یک فروشگاه لوازم خانگی است. نرم‌افزار مدیریت مشتریان و فروش (CRM) او روی یک کامپیوتر در دفتر فروشگاه اجرا می‌شود و در آدرس `http://192.168.1.220:800` فقط از داخل شبکه فروشگاه در دسترس است. آقای رضایی می‌خواهد **از خانه و در سفر، با گوشی و لپ‌تاپش** به همین CRM وصل شود — بدون اینکه هیچ پورتی از فروشگاه روی اینترنت باز شود. با همین هدف، دوربین‌های مداربسته را هم در فصل بعد اضافه خواهد کرد.

> 💡 **قبل از شروع:** خروجی‌های این فصل نمونه‌اند و جزئیات (IPها، تاریخ‌ها) روی سیستم شما متفاوت خواهد بود. در هر مرحله، تا موفقیت همان مرحله پیش بروید و بعد سراغ بعدی.

## مرحله ۱: تهیه سرور مجازی اوبونتو

اولین خرید ما یک سرور مجازی خصوصی (VPS) با سیستم‌عامل **Ubuntu 24.04** است. هنگام سفارش، این چک‌لیست را چک کنید:

| مورد لازم | مقدار پیشنهادی | چرا؟ |
|---|---|---|
| IP عمومی اختصاصی | بله | کلاینت‌ها از سراسر اینترنت به این آدرس وصل می‌شوند |
| حافظه (RAM) | حداقل ۱ گیگابایت | برای Headscale و Caddy کاملاً کافی است |
| فضای دیسک | حداقل ۱۰ گیگابایت آزاد | سیستم + پایگاه‌داده + پشتیبان‌ها |
| معماری | amd64 (یا arm64) | بسته‌های رسمی Headscale برای همین‌هاست |
| دسترسی sudo | بله (کاربر root یا کاربر با sudo) | نصب سرویس سیستمی لازم دارد |

پس از آماده‌شدن سرور، ارائه‌دهنده یک IP عمومی (مثلاً `203.0.113.10`) و رمز اولیه به شما می‌دهد. تست اتصال از کامپیوتر خودتان:

```bash
ssh root@203.0.113.10
```

اگر پرسش اثر انگشت (fingerprint) را با yes تأیید کردید و خط فرمان سرور را دیدید، مرحله اول تمام است. (ایجاد کاربر غیر از root و ورود با کلید SSH، از توصیه‌های امنیتی فصل دهم است — همین‌جا یا بعداً انجامش دهید.)

## مرحله ۲: تنظیم دامنه

آقای رضایی دامنه‌ای به نام `rezaee-shop.ir` دارد (اگر دامنه ندارید، از یک ثبت‌کننده دامنه بخرید — سالانه هزینه اندکی دارد). در پنل مدیریت دامنه، یک **رکورد A** جدید می‌سازد:

```text
نوع: A     نام: vpn     مقدار: 203.0.113.10
```

یعنی دامنه کامل سرور می‌شود: `vpn.rezaee-shop.ir`

تأیید اینکه رکورد پخش شده:

```bash
nslookup vpn.rezaee-shop.ir
```

```text
Name:    vpn.rezaee-shop.ir
Address: 203.0.113.10
```

پاسخ باید همان IP سرور باشد. اگر هنوز IP قدیمی یا خطا دیدید، چند دقیقه صبر کنید و دوباره — انتشار DNS زمان می‌برد.

## مرحله ۳: نصب با `sudo ./install.sh`

فایل‌های پروژه را روی سرور آماده می‌کنیم (روش کامل در فصل چهارم) و نصب تعاملی را اجرا می‌کنیم:

```bash
sudo ./install.sh
```

پاسخ‌های آقای رضایی به پرسش‌های نصب (فهرست کامل پرسش‌ها و توضیح هرکدام در فصل چهارم آمده؛ ترتیب ممکن است کمی متفاوت باشد):

```text
دامنه‌ای که رکورد آن به این سرور اشاره می‌کند
(مثلاً hem.example.com): vpn.rezaee-shop.ir

ایمیل برای اطلاع‌های گواهی Let's Encrypt (اختیاری): rezaee@example.com

نام اولین کاربر شبکه: admin

دامنه MagicDNS (باید با دامنه سرور متفاوت باشد): ts.rezaee-shop.ir

سرور DERP تعبیه‌شده فعال شود؟ (توصیه: بله) [بله/خیر]: بله

Caddy چگونه باشد؟ [install/reuse/skip]: install

فایروال UFW با قواعد حداقلی فعال شود؟ [بله/خیر]: بله
```

و در پایان نصب موفق:

```text
[✓] نصب کامل شد! برای شروع: hsctl status   |   آموزش: hsctl learn list
```

الان اولین نگاه به شبکه نوپای ما:

```bash
hsctl status
```

```text
سرویس headscale:         ● فعال و در حال اجرا
دامنه سرور:              https://vpn.rezaee-shop.ir
Reverse Proxy (Caddy):   ● فعال و در حال اجرا
فایروال (UFW):           فعال
کاربران:                 1
دستگاه‌ها:                0
```

## مرحله ۴: اتصال گوشی اندروید

نوبت جذاب ماجرا: گوشی آقای رضایی. اول روی سرور، یک **کلید از پیش تأییدشده (Preauth Key)** برای کاربر admin می‌سازد — یک‌بارمصرف و با اعتبار یک ساعت:

```bash
sudo hsctl preauth create admin --expiration 1h
```

```text
کلید از پیش تأییدشده برای کاربر «admin» ساخته شد:

    <AUTH_KEY>

تنظیمات: قابل استفاده مجدد = خیر | اعتبار = 1h
```

(یادآوری امنیتی فصل هشتم: کلید فقط همین یک‌بار نمایش داده می‌شود؛ همین حالا کپی‌اش کنید.)

سپس روی گوشی، طبق آموزش کامل فصل پنجم: اپ رسمی Tailscale را از فروشگاه رسمی نصب می‌کند، در تنظیمات اپ **آدرس سرور (Login Server)** را روی `https://vpn.rezaee-shop.ir` قرار می‌دهد و با کلید `<AUTH_KEY>` وارد می‌شود. لحظه‌ای بعد، در سرور:

```bash
hsctl devices list
```

```text
ID   نام دستگاه     کاربر    IP تونل     آخرین دیدن   وضعیت
1    phone-reza     admin    100.64.0.1  ۱ دقیقه پیش  متصل ✓
```

اولین عضو شبکه ثبت شد! 🎉

## مرحله ۵: اتصال لپ‌تاپ ویندوزی

لپ‌تاپ شخصی آقای رضایی ویندوزی است. طبق فصل پنجم، نرم‌افزار Tailscale برای ویندوز را از وب‌سایت رسمی نصب می‌کند. کلید مرحله قبل یک‌بارمصرف بود و مصرف شده؛ پس کلید تازه می‌گیرد:

```bash
sudo hsctl preauth create admin --expiration 1h
```

و روی لپ‌تاپ (در PowerShell با دسترسی مدیر):

```powershell
tailscale up --login-server https://vpn.rezaee-shop.ir --authkey <AUTH_KEY>
```

تست از خود لپ‌تاپ که گوشی را می‌بیند:

```text
> tailscale status
100.64.0.1  phone-reza   admin   android   -
100.64.0.2  laptop-reza  admin   windows   -
```

## مرحله ۶: راه‌اندازی ساب‌نت‌روتر در دفتر

حالا مهم‌ترین بخش معماری (فصل ششم): یک کامپیوتر همیشه‌روشن در دفتر — آقای رضایی یک مینی‌کامپیوتر قدیمی با اوبونتو را انتخاب می‌کند — که نقش **ساب‌نت‌روتر (Subnet Router)** را بازی کند و پل بین تونل و شبکه فروشگاه باشد.

روی همان کامپیوتر دفتر (که با IP داخلی مثلاً `192.168.1.50` به شبکه فروشگاه وصل است):

```bash
curl -fsSL https://tailscale.com/install.sh | sh
```

فعال‌سازی پیش‌رانش IP (شرط لازم مسیریابی):

```bash
echo 'net.ipv4.ip_forward = 1' | sudo tee -a /etc/sysctl.d/99-tailscale.conf
echo 'net.ipv6.conf.all.forwarding = 1' | sudo tee -a /etc/sysctl.d/99-tailscale.conf
sudo sysctl -p /etc/sysctl.d/99-tailscale.conf
```

اتصال به سرور همراه با پیشنهاد مسیرِ کل شبکه دفتر — یک کلید تازه دیگر از سرور بگیرید و:

```bash
sudo tailscale up --login-server https://vpn.rezaee-shop.ir --advertise-routes=192.168.1.0/24 --authkey <AUTH_KEY>
```

روی سرور، مسیر پیشنهادی را می‌بینید ولی هنوز **تأییدنشده**:

```bash
hsctl routes list
```

```text
ID   دستگاه          موجود (Advertised)   تأییدشده (Approved)   فعال
3    server-daftar   192.168.1.0/24       —                    —
```

تأیید مسیر — درِ جاده باز می‌شود:

```bash
sudo hsctl routes approve 3 --routes 192.168.1.0/24
```

> 💡 نکته: ویندوز و اندروید مسیرهای تأییدشده را خودکار می‌پذیرند؛ فقط اگر کلاینتی **لینوکسی** دارید، یک‌بار روی آن بزنید: `sudo tailscale set --accept-routes`

## مرحله ۷: لحظه موفقیت — CRM روی گوشی 🎉

آقای رضایی وای‌فای گوشی را خاموش می‌کند (تا مطمئن شود از **اینترنت همراه** می‌رود)، اپ Tailscale را روشن نگه می‌دارد، مرورگر گوشی را باز می‌کند و می‌نویسد:

```text
http://192.168.1.220:800
```

چند ثانیه بعد… **صفحه ورود CRM فروشگاه، روی گوشی، از میان اینترنت همراه بالا می‌آید!** 🎉

چه اتفاقی افتاد؟ درخواست مرورگر وارد تونل رمزنگاری‌شده شد، از سرور هماهنگی، مسیر لازم را گرفت، به ساب‌نت‌روترِ دفتر رسید، از آنجا وارد شبکه فروشگاه شد و به کامپیوتر CRM رسید؛ و پاسخش از همان مسیر برگشت. **بدون باز شدن حتی یک پورت از فروشگاه روی اینترنت.**

اگر صفحه نیامد، جای نگرانی نیست — همین حالا اولین عیب‌یابی واقعی‌تان را با الگوی فصل نهم انجام دهید (از `hsctl routes list` شروع کنید).

## مرحله ۹: اولین پشتیبان

شبکه‌ای که با زحمت ساختید را بیمه کنید:

```bash
sudo hsctl backup create
```

```text
پشتیبان ساخته شد: /var/backups/hem/hem-backup-20250116-143000.tar.gz
حجم: 2.1 MB
```

و بلافاصله راستی‌آزمایی (عادت همیشگی فصل هشتم):

```bash
hsctl backup verify hem-backup-20250116-143000.tar.gz
```

```text
✔ آرشیو سالم و قابل بازکردن است
✔ manifest.json موجود است (headscale 0.29.5 — تاریخ: 2025-01-16)
✔ پایگاه‌داده db.sqlite موجود است
✔ کلیدهای سرور موجودند
نتیجه: پشتیبان معتبر است ✅
```

طبق فصل دهم، از این فایل یک نسخه خارج از سرور (کامپیوتر شخصی یا فضای ابری رمزشده) نگه دارید.

## مرحله ۱۰: تمرین عمدی خطا — دکتر کجاست؟

بهترین متخصص‌های شبکه، کسانی‌اند که خطا را دیده‌اند و حل کرده‌اند. پس یک بار، در شرایط امن، بازی خرابی را تمرین می‌کنیم. آقای رضایی روی **سرور** می‌زند:

```bash
sudo systemctl stop headscale
```

حالا سرورِ هماهنگی خاموش است. آقای رضایی می‌داند (از فصل دهم) که اتصال‌های برقرارِ قبلی معمولاً به کارشان ادامه می‌دهند — پس صحنه را با چشمان عیب‌یاب نگاه می‌کند. روی سرور:

```bash
hsctl doctor
```

```text
✖ مشکل: سرویس headscale اجرا نمی‌شود
   علت احتمالی: توقف غیرمنتظره سرویس یا خطا در فایل پیکربندی
   چگونه بررسی شد: systemctl is-active headscale → پاسخ «inactive»
   راهکار: sudo systemctl start headscale
   اگر دوباره متوقف شد: hsctl config validate و سپس hsctl logs --lines 100

خلاصه: ۱ مشکل پیدا شد.
```

دکتر نه فقط مشکل را گفت، بلکه دستور درمانش را هم داد. اجرای درمان:

```bash
sudo systemctl start headscale
```

و کنترل نهایی:

```bash
hsctl doctor
```

```text
خلاصه: هیچ مشکلی پیدا نشد ✅
```

تمرین تمام شد — آقای رضایی دقیقاً الگوی چهار سؤالی فصل نهم را بدون آنکه اسمش را ببرد، اجرا کرد: انتظار داشتم سرویس بالا باشد / دیدم خاموش است / بین این دو، وضعیت سرویس است / پس لایه «سرویس». این چرخه را برای هر مشکلی می‌توانید تکرار کنید.

## خلاصه فصل

- ۱۰ مرحله پروژه: سرور → دامنه → نصب → گوشی → لپ‌تاپ → ساب‌نت‌روتر → لحظه موفقیت CRM → وضعیت → پشتیبان → تمرین خطا.
- کلیدهای از پیش تأییدشده را کوتاه‌عمر و یک‌بارمصرف ساختید و دیدید که چطور ثبت دستگاه را ساده می‌کنند.
- مسیر شبکه دفتر با `advertise-routes` + `routes approve` باز شد — قلب دسترسی به CRM.
- با یک توقف عمدی، چرخه واقعی عیب‌یابی (نشانه → doctor → درمان → تأیید) را تمرین کردید.
- چک‌لیست ۱۰ بندی نهایی را برای بازبینی دوره‌ای نگه دارید.

# فصل هفتم: Exit Node

در این فصل یاد می‌گیرید:

- نود خروجی (Exit Node) دقیقاً چیست و چه چیزی نیست
- چه زمانی به آن نیاز دارید و چه زمانی (مهم‌تر!) اصلاً لازمش ندارید
- تفاوت Exit Node با مسیریاب زیرشبکه (Subnet Router) در یک جدول
- فعال‌سازی آن در سه گام: اعلام، تأیید روی سرور، انتخاب روی کلاینت
- جلوگیری از نشت ترافیک (Kill Switch داخلی کلاینت)
- برگشتن به حالت عادی با یک دستور

> **هشدار مهم قبل از شروع:** Exit Node در این پروژه **به‌صورت پیش‌فرض فعال نیست و لازم هم نیست**. دسترسی به CRM دفتر (هدف اصلی این مجموعه) دقیقاً بدون آن و فقط با فصل ششم انجام می‌شود. این فصل برای موقعیت‌های خاص است که در بخش ۷.۲ می‌شناسید؛ اگر شامل حال شما نمی‌شود، با خیال راحت از آن رد شوید.

---

## ۷.۱ Exit Node چیست؟

**نود خروجی (Exit Node)** عضوی از شبکهٔ VPN است که وقتی انتخابش کنید، **کل ترافیک اینترنت دستگاه شما** — نه فقط ترافیک شبکهٔ VPN — از مسیر آن عبور می‌کند و از آن‌جا به اینترنت می‌رسد.

مقایسهٔ دو حالت روی گوشی شما:

```text
حالت عادی (پیش‌فرض — بعد از فصل ۶):

  گوشی شما ──┬── تونل VPN ──► office-router ──► CRM دفتر (فقط آدرس‌های 192.168.1.x)
             │
             └── اینترنت مخابراتی خود گوشی ──► وب‌سایت‌ها، تلگرام و… (مستقیم، مثل همیشه)


حالت Exit Node (بعد از انتخاب در این فصل):

  گوشی شما ──── همهٔ ترافیک ────► نود خروجی ────► اینترنت
             (وب‌سایت‌ها، CRM، همه‌چیز)
```

در حالت عادی، تونل VPN فقط «مقصدهای داخلی» (آدرس‌های شبکهٔ VPN و رنج‌های تأییدشده مثل `192.168.1.0/24`) را می‌بلعد؛ بقیهٔ اینترنت شما همان‌طور که بوده می‌رود. این دقیقاً همان رفتاری است که **می‌خواهیم**: سریع، بدون بار اضافه، و اینترنت گوشی دست‌نخورده.

## ۷.۲ چه زمانی لازم است و چه زمانی نیست؟

### لازم است اگر:

- **اینترنت محل اتصال ناامن است:** وای‌فای فرودگاه/هتل/کافه‌ای که به همه اعتماد ندارید و می‌خواهید همهٔ ترافیک‌تان رمزنگاری‌شده از آن‌جا خارج شود.
- **به IP ثابت یک کشور/مکان خاص نیاز دارید:** مثلاً سرویسی که فقط از IP دفتر یا سرور شما جواب می‌دهد و می‌خواهید با «هویت اینترنتی» همان‌جا ظاهر شوید.
- می‌خواهید اعضای شبکه از یک «دروازهٔ واحد و کنترل‌شده» به اینترنت بروند (سیاست‌های امنیتی خاص).

### لازم نیست اگر:

- هدف‌تان فقط دسترسی به CRM، دوربین یا فایل‌های داخل دفتر است — **این دقیقاً کار فصل ششم است و کامل انجام می‌شود.**
- فکر می‌کنید «VPN یعنی حتماً همه‌چیز باید از VPN رد شود» — نه؛ این معماری فقط مسیرهای لازم را تونل می‌کند و این بهتر است.
- می‌خواهید اینترنت پرسرعت گوشی دست‌نخورده بماند (عبور همهٔ ترافیک از یک نود، پهنای باند آن نود را مصرف می‌کند و می‌تواند سرعت را محدود کند).

> **نکتهٔ مهم مأموریت:** بدون فعال‌کردن Exit Node، اینترنت عادی گوشی/لپ‌تاپ شما دقیقاً از مسیر خودش می‌رود (مخابرات، وای‌فای خانه و…) و فقط ترافیک شبکهٔ VPN از تونل عبور می‌کند. **این رفتار مطلوب و پیش‌فرض است** — نه نقص، نه فراموشی!

## ۷.۳ تفاوت Exit Node با Subnet Router

این دو، تنها «نقش‌های ویژهٔ» دستگاه‌ها در این شبکه‌اند و اشتباه‌گرفتنشان رایج است:

| | مسیریاب زیرشبکه (Subnet Router) — فصل ۶ | نود خروجی (Exit Node) — همین فصل |
|---|---|---|
| چه چیزی را مسیر می‌دهد؟ | یک **رنج مشخص** (مثلاً `192.168.1.0/24`) | **همهٔ اینترنت** (`0.0.0.0/0` یعنی هر مقصدی) |
| هدف | دسترسی به دستگاه‌های داخل شبکهٔ دفتر | خروج کل ترافیک اینترنت از یک نقطه |
| روی سرور چه تأیید می‌شود؟ | رنج `192.168.1.0/24` | رنج `0.0.0.0/0` |
| بعد از فعال‌بودن، اینترنت دستگاه عوض می‌شود؟ | نه — فقط مقصدهای همان رنج از تونل می‌روند | بله — همه‌چیز از نود خروجی می‌رود |
| در این پروژه | **هستهٔ اصلی راه‌حل** | اختیاری، برای سناریوهای خاص |
| مثال تشبیهی | «پل ورود به شهرک صنعتی» | «اتوبان خروجی کل شهر» |

## ۷.۴ فعال‌سازی در سه گام

فرض: می‌خواهیم دستگاه `office-router` (همان دستگاه فصل ششم، یا هر عضو دیگری مثل خود VPS… هر دستگاه عضو می‌تواند باشد) نود خروجی شود و لپ‌تاپ لینوکسی شما از آن استفاده کند.

### گام ۱ — روی نودِ خروجی: اعلام

روی دستگاهی که قرار است «دروازهٔ اینترنت» شود (اگر از قبل عضو شبکه است):

```bash
sudo tailscale set --advertise-exit-node
```

توضیح: به کلاینت می‌گوییم «خودت را به‌عنوان نود خروجی معرفی کن». (مستندات رسمی Tailscale توصیه می‌کنند بعد از `set --advertise-exit-node` یک‌بار هم `tailscale up` بزنید.)

اگر دستگاه تازه می‌خواهد عضو شود، این را موقع عضویت بدهید:

```bash
sudo tailscale up --login-server https://headscale.example.com --advertise-exit-node
```

**اگر نود خروجی شما ویندوزی است:** برخلاف نقش «مسیریاب زیرشبکه» (فصل ششم) که فقط لینوکسی پشتیبانی می‌شود، نقش «نود خروجی» طبق مستندات رسمی Tailscale روی ویندوز هم پشتیبانی می‌شود. همان دستورها بدون `sudo` در PowerShell/CMD ویندوز:

```powershell
tailscale set --advertise-exit-node
tailscale up
```

یا از رابط گرافیکی برنامهٔ Tailscale ویندوز: بخش Exit Node ← گزینهٔ «Run as exit node».

### گام ۲ — روی سرور: تأیید

مثل Route فصل ششم، این ادعا هم باید روی سرور تأیید شود. اول ببینید (روی سرور — از ویندوز: `ssh ubuntu@203.0.113.10 "hsctl routes list"` طبق الگوی بخش ۴.۰):

```bash
hsctl routes list
```

خروجی نمونه:

```text
ID | Hostname       | Approved       | Available       | Serving (Primary)
1  | office-router  | 192.168.1.0/24 | 192.168.1.0/24, 0.0.0.0/0 | 192.168.1.0/24
```

در ستون Available یک پیشنهاد تازه می‌بینید: `0.0.0.0/0` (یعنی «همهٔ اینترنت»). تأییدش کنید (روی سرور):

```bash
hsctl routes approve 1 --routes 0.0.0.0/0
```

از ویندوز، معادل یک‌خطی (بخش ۴.۰):

```powershell
ssh ubuntu@203.0.113.10 "sudo hsctl routes approve 1 --routes 0.0.0.0/0"
```

(دستور sudo است؛ اگر سرور رمز sudo بخواهد، نشست تعاملی SSH باز کنید یا `ssh -t` بزنید — بخش ۴.۰. تأیید مسیرها از رابط گرافیکی پنل هم ممکن است — فصل شانزدهم.)

یا معادل خام:

```bash
headscale nodes approve-routes --identifier 1 --routes 0.0.0.0/0
```

نکتهٔ فنی خوب: **تأیید همین `0.0.0.0/0` (نسخهٔ IPv4) کافی است؛** مسیر IPv6 معادل (`::/0`) به‌صورت خودکار همراه آن تأیید می‌شود.

> اگر می‌خواهید دستگاه هم مسیریاب زیرشبکه باشد و هم نود خروجی، در دستور approve می‌توانید هر دو را با هم بدهید: `hsctl routes approve 1 --routes 192.168.1.0/24,0.0.0.0/0`

### گام ۳ — روی دستگاه مصرف‌کننده: انتخاب نود خروجی

روی دستگاهی که می‌خواهد اینترنتش از آن‌جا برود (مثلاً لپ‌تاپ لینوکسی شما):

```bash
sudo tailscale set --exit-node office-router
```

توضیح خط‌به‌خط:

- `sudo tailscale set` : تغییر تنظیمات کلاینتِ در حال اجرا
- `--exit-node office-router` : «نود خروجی من این باشد» (نام دستگاه عضو — همان نامی که در `tailscale status` می‌بینید)

روی ویندوز، همین انتخاب هم از رابط گرافیکی برنامهٔ Tailscale (آیکون سینی ← بخش Exit Node ← انتخاب دستگاه) و هم با همان دستور در PowerShell/CMD (بدون sudo) انجام می‌شود:

```powershell
tailscale set --exit-node office-router
```

از همین لحظه، همهٔ ترافیک اینترنت این دستگاه از `office-router` می‌رود.

بررسی سریع: اگر IP عمومی خود را در یک سایت «IP من چیست» ببینید، باید IP نود خروجی را نشان بدهد، نه IP قبلی دستگاه شما.

## ۷.۵ جلوگیری از نشت ترافیک (Kill Switch)

**نشت ترافیک (Traffic Leak)** یعنی: اگر تونل VPN وسط کار قطع شود، آیا ترافیک شما بی‌اجازه از مسیر عادی (رمزنگاری‌نشده) ادامه می‌دهد؟

خبر خوب: کلاینت‌های رسمی Tailscale گزینهٔ داخلی (built-in) برای همین کار دارند. در اندروید، تنظیمِ سیستمی «Block connections without VPN» (مسدودسازی اتصال بدون VPN) را که در تنظیمات برنامه/سیستم می‌بینید فعال کنید تا اگر تونل قطع شد، هیچ ترافیکی از مسیر عادی و رمزنگاری‌نشده خارج نشود؛ در ویندوز و لینوکس هم حالت مشابهی با تنظیمات کلاینت و قواعد فایروال همراه آن قابل حصول است. اگر دلیلِ استفاده‌تان از Exit Node امنیت است، فعال‌کردن این گزینه را جدی بگیرید.

تست سادهٔ اطمینان: بعد از فعال‌کردن Exit Node، روی دستگاه نود خروجی کلاینت را موقتاً قطع کنید (روی لینوکس `sudo tailscale down`؛ روی ویندوز `tailscale down` در PowerShell یا کلید خاموش در برنامهٔ Tailscale) — دستگاه مصرف‌کننده باید «بدون اینترنت» بماند، نه اینکه از مسیر عادی ادامه دهد. اگر چنین بود، نشتی در کار نیست.

## ۷.۶ برگشتن به حالت عادی

هر وقت خواستید اینترنت دستگاه‌تان مثل قبل مستقیم برود:

- **در رابط گرافیکی** (اندروید/ویندوز): گزینهٔ Exit Node را در برنامهٔ Tailscale خاموش کنید.
- **در خط فرمان لینوکس** — توجه کنید که مقدار بعد از `=` خالی است:

```bash
sudo tailscale set --exit-node=
```

- **در ویندوز (PowerShell/CMD)** — همان دستور بدون sudo:

```powershell
tailscale set --exit-node=
```

توضیح: انتخابِ «هیچ» به‌عنوان نود خروجی — از این لحظه فقط ترافیک شبکهٔ VPN (مثل مسیر `192.168.1.0/24` فصل ششم) از تونل می‌رود و اینترنت شما مستقیم، مثل روز اول.

اگر روزی خواستید خودِ «عرضهٔ» نود خروجی را هم برچینید، روی آن دستگاه اعلام را در تنظیمات کلاینت (همان‌جایی که فعالش کردید) بردارید و اگر لازم شد تأیید مسیر روی سرور را هم با `hsctl routes revoke` پس بگیرید (جزئیات در [فصل هشتم: مدیریت روزمره](08-modiriyat-roozmareh.md)).

## خلاصه فصل

- Exit Node یعنی عبور «کل ترافیک اینترنت» یک دستگاه از یک عضو انتخابی شبکه — در تضاد با حالت عادی که فقط مقصدهای داخلی از تونل می‌روند.
- برای اینترنت ناامن یا نیاز به IP ثابت یک مکان، مفید است؛ برای دسترسی به CRM **کاملاً غیرلازم** — آن کار فصل ششم است.
- تفاوت با Subnet Router: آن‌یکی مسیر «ورود به یک رنج مشخص» است، این‌یکی «خروج به کل اینترنت» (`0.0.0.0/0`).
- سه گام: روی نود `sudo tailscale set --advertise-exit-node` (در ویندوز بدون sudo هم پشتیبانی می‌شود)؛ روی سرور `hsctl routes approve <ID> --routes 0.0.0.0/0` (IPv6 خودکار همراهش تأیید می‌شود)؛ روی مصرف‌کننده `sudo tailscale set --exit-node <NAME>` (ویندوز: برنامهٔ Tailscale یا همان دستور بدون sudo).
- ضدنشت: کلاینت‌های رسمی به‌صورت داخلی جلوی ادامهٔ مسیر رمزنگاری‌نشده را می‌گیرند؛ با قطع‌کردنِ آزمایشی تونل می‌توانید مطمئن شوید.
- بازگشت: خاموش‌کردن گزینه در برنامه یا `sudo tailscale set --exit-node=` (ویندوز: `tailscale set --exit-node=`).
- و باز هم تأکید: در این پروژه Exit Node پیش‌فرض خاموش است و همین درست است.

شبکهٔ شما کامل است: سرور نصب، دستگاه‌ها وصل، پل دفتر آماده. از این‌جا به بعد دربارهٔ «نگه‌داشتن» این شبکه حرف می‌زنیم — وضعیت، کاربران، کلیدها و پشتیبان‌گیری: [فصل هشتم: مدیریت روزمره](08-modiriyat-roozmareh.md)

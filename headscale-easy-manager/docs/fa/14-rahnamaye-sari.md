## در این فصل یاد می‌گیرید

- با چه وسایلی می‌توانید همین امروز شروع کنید
- مسیر نصب تا اولین اتصال را در **پنج گام** ببینید
- ده دستور پرکاربرد `hsctl` را یکجا داشته باشید
- برای هر خواسته‌ای، بدانید کدام فصل را باز کنید

این فصل، برگه‌ی جیبی شماست — نه جای آموزش کامل را می‌گیرد نه می‌خواهد حافظه‌تان باشد؛ فقط نقشه‌ای سریع برای وقتی که وقت کم است.

## چه چیزی لازم دارم؟

| وسیله | حداقل مشخصات | یادداشت |
|---|---|---|
| سرور مجازی (VPS) | اوبونتو ۲۲.۰۴/۲۴.۰۴، IP عمومی، ۱GB رم، ۱۰GB دیسک، دسترسی sudo | میزبان سرور Headscale شما |
| یک دامنه | هر دامنه‌ای که پنل مدیریت رکورد دارد | زیردامنه‌ای مثل `vpn.example.com` کافی است |
| دستگاه‌های شما | گوشی اندروید/iOS یا لپ‌تاپ ویندوز/مک/لینوکس | هر دستگاهی که Tailscale برایش دارد |
| یک کامپیوتر همیشه‌روشن در دفتر | فقط اگر می‌خواهید به CRM/دوربین دفتر برسید (فصل ۶) | نقش ساب‌نت‌روتر را بازی می‌کند |

## پنج گام از صفر تا اتصال

**گام ۱ — ورود به سرور:** از کامپیوتر خودتان به سرور مجازی وصل شوید:

```bash
ssh root@<IP-سرور>
```

**گام ۲ — رکورد دامنه:** در پنل دامنه، رکورد A را به IP سرور اشاره دهید و تأیید بگیرید:

```bash
nslookup vpn.example.com
```

**گام ۳ — نصب:** روی سرور، در پوشه پروژه:

```bash
sudo ./install.sh
```

(پرسش‌ها و جزئیات کامل: فصل چهارم)

**گام ۴ — اتصال اولین دستگاه:** روی سرور یک کلید از پیش تأییدشده (Preauth Key) بسازید:

```bash
sudo hsctl preauth create admin --expiration 1h
```

روی دستگاه لینوکسی (یا در PowerShell ویندوز):

```bash
sudo tailscale up --login-server https://vpn.example.com --authkey <AUTH_KEY>
```

(گوشی‌ها و لپ‌تاپ‌ها: فصل پنجم — دسترسی به CRM دفتر: فصل ششم)

**گام ۵ — تأیید نهایی:**

```bash
hsctl status
hsctl doctor
```

هر دو سبز؟ تبریک، شبکه خصوصی شما زنده است. 🎉

> ⏱️ اگر هر گامی بیش از چند دقیقه گیر کرد، فصل ۹ (عیب‌یابی) را باز کنید — احتمالاً یکی از همان ۱۴ خطای رایج است که آنجا نقشه رفعش آمده.

## ده دستور پرکاربرد hsctl

| دستور | برای چه لحظه‌ای؟ |
|---|---|
| `hsctl status` | نگاه روزانه به وضعیت کلی |
| `hsctl doctor` | اولین دستور در هر مشکلی |
| `hsctl logs --lines 100` | دیدن آخرین رخدادهای سرویس |
| `hsctl users list` | چه کسانی در شبکه‌اند |
| `sudo hsctl users create <name>` | همکار جدید |
| `hsctl devices list` | چه دستگاه‌هایی وصل‌اند |
| `sudo hsctl devices delete <id>` | حذف دستگاه (با احتیاط و تأیید!) |
| `sudo hsctl preauth create <user> --expiration 1h` | «کد دعوت» برای دستگاه جدید |
| `hsctl routes list` | وضعیت مسیر شبکه دفتر |
| `sudo hsctl backup create` | پشتیبانِ بعد از هر تغییر مهم |

دو دستور کمکی هم فراموش نشود: `hsctl learn list` فهرست همین فصل‌ها را روی سرور می‌آورد و `hsctl explain <topic>` مفاهیم (مثل `routes`، `preauthkey`، `backup`) را کوتاه توضیح می‌دهد.

## دستورهای سمت دستگاه‌ها (کلاینت Tailscale)

سمت سرور با `hsctl` کار می‌کنید؛ روی خود دستگاه‌ها هم این پنج دستور پرکاربردِ Tailscale را داشته باشید:

| دستور | کجا؟ | برای چه؟ |
|---|---|---|
| `tailscale status` | لپ‌تاپ لینوکسی/سرور دفتر | چه دستگاه‌هایی می‌بینم و وضعیت‌شان چیست |
| `tailscale ping <IP-یا-نام>` | هر کلاینت | تست رسیدن به یک دستگاه از داخل تونل |
| `tailscale ip -4` | هر کلاینت | IP تونلِ خودم را ببینم |
| `sudo tailscale set --accept-routes` | فقط کلاینت لینوکسی | پذیرش مسیرهای شبکه دفتر (ویندوز/اندروید خودکار است) |
| `sudo tailscale up --login-server https://<دامنه>` | کلاینت جدید | اتصال به سرور خودمان |

## پرسش‌های سریع

**چطور بفهمم همه‌چیز سالم است؟** — `hsctl status` و `hsctl doctor` هر دو بدون قرمزی. همین.

**گوشی با اینترنت همراه هم وصل می‌شود؟** — بله؛ VPN روشن باشد و آدرس‌های داخلی (مثل CRM و NVR) فقط از داخل تونل باز می‌شوند — تست پذیرش کامل در فصل ۱۳.

**اگر اینترنت دفتر از نوع CGNAT (ترجمه آدرس در سطح اپراتور) باشد چه؟** — هیچ مشکلی نیست؛ دقیقاً برای همین معماری انتخاب شده — هیچ پورتی از دفتر لازم نیست باز شود.

**کلیدم را گم کردم / دوباره نشان بده!** — کلید از پیش تأییدشده فقط یک‌بار نمایش داده می‌شود؛ به‌جای جست‌وجوی آن، کلید تازه بسازید: `sudo hsctl preauth create <user> --expiration 1h`

**یکی از دستگاه‌ها از دست رفت، چه کنم؟** — فصل ۱۰: حذف دستگاه از تونل، رسیدگی به کلیدها، تغییر رمز سرویس‌ها.

**نصب چقدر طول می‌کشد؟** — روی یک VPS آماده و با رکورد درست دامنه، معمولاً کمتر از ۱۰ دقیقه تا اولین اتصال.

**روی چند دستگاه می‌توانم وصل شوم؟** — هر تعداد که بخواهید؛ هر دستگاه یک ردیف در `hsctl devices list` است و مدیریت همه از همین یک سرور انجام می‌شود.

**حالا که این صفحه را خواندم، از کجا شروع کنم؟** — از همان پنج گام بالا؛ و اگر دوست دارید با یک داستان کامل پیش بروید، فصل ۱۲ همه این گام‌ها را در قالب یک پروژه واقعی تمرین می‌کند.

## سه نکته طلایی ایمنی

1. **هیچ پورت مدیریتی روی اینترنت باز نکنید** — نه دوربین، نه CRM، نه پنل‌ها. همه دسترسی‌ها فقط از درون تونل. (فصل ۱۰ و ۱۳)
2. **کلیدهای از پیش تأییدشده را کوتاه‌عمر بسازید** (`--expiration 1h`)، فقط یک‌بار نمایش داده می‌شوند — همان لحظه کپی و امن منتقل کنید. (فصل ۸)
3. **پشتیبان منظم + راستی‌آزمایی** — بعد از هر تغییر مهم: `backup create` و بعد `backup verify <FILE>`؛ و هر شش ماه یک بازیابی آزمایشی روی سرور موقت. پشتیبان آزمایش‌نشده، پشتیبان نیست. (فصل ۱۰)

> 🔁 این سه نکته را کنار تقویم نگهداری فصل ۱۰ بگذارید: هفتگی `status` و `doctor` و پشتیبان، ماهانه `verify`، شش‌ماهه بازیابی آزمایشی — مجموعاً کمتر از نیم ساعت در ماه، در ازای آرامش کامل.

## خلاصه فصل

- سه وسیله لازم دارید: VPS اوبونتو، یک دامنه، دستگاه‌هایتان (+ یک کامپیوتر روشن در دفتر برای دسترسی به CRM).
- پنج گام: SSH → رکورد A → `sudo ./install.sh` → اتصال کلاینت با `tailscale up --login-server` → `hsctl status`.
- ده دستور پرکاربرد hsctl را دارید؛ برای هر خواسته‌ای هم فصل مربوطه معرفی شد.
- سه قانون طلایی: پورت باز نکنید، کلیدها کوتاه‌عمر و امن، پشتیبان منظم و آزموده.

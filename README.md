# Headscale Easy Manager

**نصب‌کننده هوشمند، مدیر CLI و راهنمای جامع فارسی برای راه‌اندازی شبکه خصوصی مبتنی بر Headscale**

این ابزار برای کسانی ساخته شده که می‌خواهند شبکه خصوصی خودشان را با Headscale (نسخه مستقل و متن‌باز سرور کنترل Tailscale) روی یک VPS راه بیندازند — بدون آنکه متخصص لینوکس، شبکه یا VPN باشند. برنامه مراحل فنی را خودش انجام می‌دهد، در هر قدم به فارسی توضیح می‌دهد، خطاها را تشخیص می‌دهد و در پایان یک شبکه قابل استفاده و مستند تحویل می‌دهد.

> **نسخه هدف:** Headscale **v0.29.5** (راستی‌آزمایی‌شده از سورس رسمی) — همه حقایق فنی پروژه در [`docs/FACTS.md`](docs/FACTS.md) مستند است.

---

## چه کاری برای شما انجام می‌دهد؟

- ✅ **نصب با یک دستور:** از یک VPS خام اوبونتو تا سرور Headscale فعال با HTTPS معتبر
- ✅ **بررسی پیش‌نیازها:** سیستم‌عامل، معماری، دیسک، RAM، پورت‌های اشغال‌شده، سرویس‌های موجود
- ✅ **احترام به سرور موجود:** Caddy/Headscale از قبل نصب‌شده را تشخیص می‌دهد، قبل از هر تغییری پشتیبان می‌گیرد و سرویس‌های نامرتبط را دست نمی‌زند
- ✅ **فایروال امن:** پورت SSH شما همیشه اول مجاز می‌شود — قفل‌شدن بیرون از سرور عملاً غیرممکن است
- ✅ **مدیریت کامل پس از نصب:** کاربران، دستگاه‌ها، کلیدهای اتصال، مسیرها (Routes)، پشتیبان‌گیری، به‌روزرسانی، عیب‌یابی — همه با یک ابزار: `hsctl`
- ✅ **دسترسی به شبکه دفتر:** راهنمای گام‌به‌گام Subnet Router برای دسترسی به CRM و دستگاه‌های داخلی دفتر (مثل `192.168.1.220:800`)
- ✅ **دوربین‌های مداربسته:** دسترسی امن به دستگاه ضبط (NVR/DVR) و دوربین‌ها از راه دور، بدون باز کردن هیچ پورتی روی اینترنت
- ✅ **مرکز آموزش فارسی:** ۱۴ فصل آموزشی مبتدی‌پسند داخل خود ابزار (`hsctl learn`)

## پیش‌نیازها

| مورد | جزئیات |
|---|---|
| سرور (VPS) | Ubuntu Server 22.04 یا 24.04 LTS — amd64 (یا arm64) — حداقل ۱GB RAM و ۱۰GB فضای آزاد — IP عمومی |
| دامنه | یک زیردامنه (مثل `headscale.example.com`) که بتوانید رکورد A آن را به IP سرور تنظیم کنید |
| دسترسی | اتصال SSH به سرور با دسترسی sudo |
| کلاینت‌ها | اپ رسمی Tailscale روی اندروید/iOS/ویندوز/macOS/لینوکس (رایگان) |

> Ubuntu 22.04 پشتیبانی رسمی دارد؛ Debian 12+ با هشدار «آزمایش‌نشده» قابل استفاده است.

## نصب — شروع سریع

پس از ورود به سرور با SSH و دریافت این مخزن (کلون یا بارگذاری فایل‌ها):

```bash
cd headscale-easy-manager
sudo ./install.sh
```

نصب‌کننده تعاملی است: دامنه از شما می‌پرسد، DNS را بررسی می‌کند، اگر مشکلی باشد راهنمایی می‌کند و در پایان گزارش کامل نصب و دستورات اتصال را نشان می‌دهد.

### حالت خودکار (برای اتوماسیون)

```bash
cp examples/hem-install.conf.example hem-install.conf
nano hem-install.conf        # مقادیر خودتان را وارد کنید
chmod 600 hem-install.conf   # این فایل را محافظت کنید!
sudo ./install.sh --config hem-install.conf --non-interactive
```

### حالت آزمایشی (Dry-Run)

```bash
sudo ./install.sh --dry-run   # فقط نمایش تغییرات، بدون اعمال هیچ‌چیز
```

## ابزار مدیریت: `hsctl`

| دستور | کار |
|---|---|
| `hsctl status` | وضعیت کلی سرور، سرویس‌ها، DNS، پورت‌ها و دیسک |
| `hsctl doctor` | عیب‌یابی خودکار (مشکل / علت / نحوه بررسی / راهکار) — با `--fix` اصلاح کم‌خطر |
| `hsctl logs --lines 100` | مشاهده لاگ سرویس |
| `hsctl users create sara` | ساخت کاربر جدید |
| `hsctl devices list` | فهرست دستگاه‌های متصل |
| `hsctl preauth create admin --reusable --expiration 24h` | ساخت کلید اتصال از پیش تأییدشده |
| `hsctl routes list` / `hsctl routes approve <id> --routes 192.168.1.0/24` | مدیریت مسیرهای شبکه دفتر |
| `hsctl backup create` / `hsctl backup verify <FILE>` / `hsctl restore <FILE>` | پشتیبان‌گیری و بازیابی |
| `hsctl update --check` | بررسی و به‌روزرسانی امن (نسخه‌به‌نسخه) |
| `hsctl cameras add` / `hsctl cameras check` | مدیریت و تست دسترسی دوربین/NVR |
| `hsctl learn list` / `hsctl learn 6` / `hsctl explain subnet-router` | مرکز آموزش فارسی |
| `hsctl report` | گزارش قابل‌ارسال برای پشتیبانی (بدون اطلاعات حساس) |
| `hsctl uninstall` | حذف — فقط کارهای خود ابزار؛ پشتیبان‌ها حفظ می‌شوند |

راهنمای کامل هر دستور: `hsctl --help` و فصل هشتم مستندات (`hsctl learn 8`).

## امنیت

- دانلود بسته Headscale فقط از **ریلیز رسمی GitHub** + راستی‌آزمایی **SHA-256** از فایل رسمی `checksums.txt`
- هیچ رمز/کلیدی در لاگ، خروجی یا گزارش چاپ نمی‌شود (لایه محوسازی خودکار)
- هر عملیات مخرب نیازمند تأیید صریح است؛ همه تغییرات در `/etc/hem/state.json` ثبت می‌شوند تا حذف نصب بتواند دقیقاً فقط کارهای خودمان را برگرداند
- گواهی TLS معتبر Let's Encrypt با تمدید خودکار (از طریق Caddy) — بدون هیچ تنظیم TLS ناامن
- فایروال با اصل حداقل دسترسی: فقط 80/443 (و 3478/udp در صورت فعال‌بودن DERP تعبیه‌شده)
- جزئیات: [`SECURITY.md`](SECURITY.md)

همین فصل‌ها داخل CLI هم در دسترس‌اند: `hsctl learn list`

```
├── scripts/          # ابزارهای توسعه
└── tests/            # تست‌های pytest
```

## توسعه و تست

```bash
python3 -m pip install -e ".[dev]"   # نصب قابل‌ویرایش + ابزار توسعه
make test                            # اجرای تست‌ها
make lint                            # بررسی کیفیت کد (ruff)
```

تست‌های واحد (۵۳ تست: رندر پیکربندی، پارس checksums، DNS، بلوک Caddy، پشتیبان، دوربین‌ها، learn، CLI) در هر محیط لینوکسی اجرا می‌شوند.

> **صراحت درباره محدوده تست:** تست‌های یکپارچه واقعی (نصب کامل روی VPS، systemd، UFW، صدور گواهی واقعی، اتصال کلاینت واقعی) باید روی **سرور آزمایشی Ubuntu 22.04/24.04** اجرا شوند؛ در محیط توسعه این پروژه، منطق نرم‌افزار با تست واحد پوشش داده شده است. سناریوی تست پیشنهادی VPS آزمایشی در فصل ۱۲ مستندات آمده است.
